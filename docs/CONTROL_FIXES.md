# 最近的运动规划与反馈修复

本项目仍在开发。以下代码和模拟检查不能替代你的机械臂尺寸、参考点、P角度映射和现场路径标定；真实视觉抓取、五轮可靠搬运和10秒指标尚未完成验收。

## 通用任务与低位恢复

`src/arm_project/general_transfer_entry.py`从本次新鲜反馈计算名义姿态，经直连或有限RRT-Connect路线进入工作起点，再由同一个任务运行器连接准备和循环。每次主动任务使用独立预算，历史失败动作不自动续跑。

正净空内但未达到普通预留余量的姿态，可由`clearance_recovery.py`和`table_escape.py`尝试受约束脱离。恢复过程逐边检查，进入普通场景后不再启用临时例外；负净空、自碰撞、障碍和超限不因此放行。所有毫米量都是名义模型量，真实几何与连续扫掠仍待验证。

`route_timing.py`修复了固定二分把可行三段变成四段后误拒的问题。`timed_cycle.py`从最后一个目标发送完成后给予完整声明T，发送/日志开销仍计入任务总期限，运动过程中只读反馈，不在每个几何采样点停顿。

## 逐轴容差通过仍可能组合失败

一次实际下降的001/002/003目标为1331/2163/1221P，反馈为1320/2170/1200P，误差为-11/+7/-21P，分别落在当时20/35/35P交接容差内。但组合后名义包络净空为-3.17mm，触发桌面检查。该数值是模型计算，不是实际碰桌证据；实物参考点与模型的高度也仍待核对。

新增`handoff_envelope.py`按最终任务传播目标、保持轴和未命令轴的交接区间，使用连续角区间正弦极值及有限细分检查非入口工作阶段桌面余量。角点仅用于寻找反例，不用来证明整个误差区间都通过。失败在建立运动门禁和消费预算前报告`HANDOFF_BLOCKED`，保存`handoff_envelope.json`。

这一检查不自动缩小现场容差，也不平移桌面或修改工具长度。交接状态通过不证明真实多轴同步、自碰撞/障碍模型完备、实际抓取或物理停止。测试中的小误差成功替身是数学对照，不能当成你的硬件精度。

## 可追溯的失败记录

执行器拒绝几何姿态时保存`task_scene_rejected`事件，含完整六轴输入、阶段和检查结果。恢复检查器只调用一次`inspect`，避免重复推进状态。启动规划失败也保存`entry_plan.json`和`input_snapshot.json`，后续改配置不会覆盖原快照。

`tools/inspect_transfer_failure.py`只读取已有任务目录，用当次参数重算名义场景，不连接串口或相机。新版优先读取明确拒绝事件；旧版结合完整端点回读和对应回复恢复组合，证据不足报告`UNCERTAIN`，不拿最后成功采样冒充失败姿态。

在已安装开发依赖的仓库根运行（替换为你自己的已结束任务和未存在的新输出目录）：

```bash
# 只读分析；原运行目录和旧报告不会覆盖，不会发送运动指令。
python tools/inspect_transfer_failure.py --run-dir /path/to/finished-run --output artifacts/inspection-new
```

普通读者先走[离线快速开始](QUICKSTART.md)。需要实际运动时阅读[有限运动控制原理](FINITE_MOTION.md)，使用你自己的现场测量与审阅，不复用作者旧动作预算或本机启用策略。
